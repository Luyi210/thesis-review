# 学院论文审核工作台 0.8.0

本机浏览器提供页边批注。左侧显示上传的 Word 或 PDF 原稿，点击标记，右侧显示该处的格式或材料要求、修改建议和学院指南页码。同一位置的多个问题归在一起，可点选其中一条查看对应建议。学生在 Word 或 WPS 中修改，然后重新上传。

[打开论文审阅工作台](https://luyi210.github.io/thesis-review/)

## 使用

在这台电脑双击 `打开工作台.command`。本机预览地址为 `http://127.0.0.1:5178/`，预览进程只监听本机。关闭终端或 Ctrl+C 停止服务。从 GitHub 克隆源码后，先执行开发一节的安装与本地构建命令。启动器不会自动安装软件或下载模型。

选择审核阶段，上传 DOCX/PDF，或点击“打开示例稿”。使用原文标记或右侧上一处、下一处查看批注。顶部“更多工具”（···）内可查完整检查记录、图表与公式、版本对比和更多样稿。示例稿为合成材料。

对于文字型 PDF，工作台能对照同稿页脚中连续编号的脚注。例如，已有完整的 `[26]` 时，可将下一条的 `27]` 标出，并建议补成 `[27]`。这类批注保留原编号，依据和改法均来自本稿，在浏览器中即可完成。

点击“打开示例稿”可查看一段同时包含 10.5 磅“输入电压”和 14 磅“输出电压”的正文。页边批注引用对应文字和实测值。Word 预览与原生文字完全一致、且浏览器支持自定义高亮时，可在预览中突出当前文字片段。其余情况保留段落定位。PDF 的字号提示仍定位到可读取的文字行。

默认修改建议来自规则。需要额外说明时，在当前批注展开「补充解释」，点「下载或加载本机模型」，完成后点「用本地模型解释这一处」。首次准备默认 1.7B 量化模型约需下载 984 MB，之后可复用浏览器缓存。模型输入绑定本次检查、规则、证据位置和该位置的判定状态。

教师可在一处批注下展开“教师反馈”，分别评价问题判断和修改建议，填写自己的改法。在“更多工具 → 教师反馈”中可登记漏报、查找 Word 段落、查看和导出本次页面会话的记录。刷新前请导出；导出的 JSON 包含选中位置的原文摘录及意见。

开发预览的 Node.js 由开发者配置。将构建产物发布为 HTTPS 网页后，学生无需安装 Node.js、Python、Ollama；浏览器与硬件仍需支持 WebGPU。GitHub Pages 提供可分享的静态网页。通用模型使用 WebLLM 预置地址，学院微调版使用独立的模型仓库。两者均在浏览器推理，论文内容留在本机。

## 技术与边界

| 组件 | 当前实现 |
| --- | --- |
| React / TypeScript / Vite | 上传、原文预览、批注联动、阶段切换、配置与 JSON 导出 |
| DOCX 原生解析 | OOXML 样式继承、中文字体/字号/字距、固定行距、A4、栏目与摘要线索；读取主文档块顺序、表格合并标记、绘图与 OMML 对象 |
| 图表题注核对 | 对可唯一关联的单张行内图片及非浮动、非嵌套表格，核对相邻题注源顺序、可读所在章号、重复和倒序编号；不擅自要求编号连续 |
| 对象覆盖清单 | 分对象列出题注关联、各项结果与未审核范围；可定位图片所在段、整张表格或公式所在段。模型不参与这些判断 |
| docx-preview | 浏览器排版预览；用源段号和文本复核定位。无法唯一定位时明确提示，不猜测；不承诺与 Word 分页一致 |
| PDF.js | 根据原生文字位置和绘图边界识别重复页眉页脚、有分隔线的脚注、与图像或网格相邻的题注及网格表内文字。其余候选正文按行核对字号，完整检查记录可查看范围统计 |
| 学院规则 | 从原核心复用 41 条规则/人工核对项及哈希绑定的指南，按阶段应用；仅部分自动执行，其他显示人工确认 |
| WebLLM Worker | 本地 Qwen3 单条证据解释、JSON 约束、阶段 Skill、预算、超时与取消；不改原文、不改变规则判定 |
| PWA | 缓存页面及 PDF 运行资源；模型由 WebLLM 单独缓存。完整断网重启推理仍需独立验证 |

高级图片 OCR、PDF 复杂表格、三线表、跨页关系和公式图片识别尚未接入浏览器。Python 原型中的 Tesseract 不等于本页具备 OCR。公式只定位原生 OMML，未审核公式排版、编号或数学正确性。多图共用题注、混排文字、浮动/嵌套对象、隐藏/修订内容、未唯一归属题注保留人工确认。复杂对象未覆盖时不据此认定全文材料缺失。纯扫描件仍可预览，但不能宣称已识别文字。PDF 对象清单为零不等于没有图表公式。

字数、综述比例、参考文献完整规范等未移植的项目显示“人工确认”，不能算通过。指南规则仍需学院教师确认；中期进度不等同于字数比例。

## 模型、Skill 与微调

`public/skills/` 是三个阶段的解释指令与工具合同；`public/rules/college.json` 记录学院依据。开题批注 LoRA 在开发电脑上独立训练和评测。“更多工具 → 教师反馈 → 准备微调样例”导出当前范围内教师确认判定正确、并亲自改写的逐条建议。草案含所选证据、规则依据、教师原话和文稿版本哈希，导出后需审阅与去标识，并把同一篇论文的不同版本放入同一个数据分组。任何反馈都不会自动触发训练。

公开工作台可以在「补充解释」一键下载并自动加载学院第三轮微调试用版。`.env.production` 中的 `VITE_COLLEGE_MODEL_URL` 指向完整 WebLLM 权重的固定 Hugging Face 版本。自定义地址须保留 `/resolve/<revision>/` 路径，并允许跨域读取模型文件。开发时可以用本机回环 HTTP 地址。首次点击下载约 1 GB，之后浏览器可复用缓存。稿件核对、固定行距和脚注的修改建议继续使用学院规则。

下一步按论文划分去标识教师标注数据与独立测试集，先比较原始模型＋Skill 基线。确认改进后再做开发侧 SFT/LoRA、合并/量化、MLC 转换和编译、浏览器复测。硬性数值始终由规则读取证据后判定。

## 开发

Node.js 22+；使用已附锁文件。`pnpm install --frozen-lockfile`、`pnpm run prepare:assets`、`pnpm test`、`pnpm build`、`pnpm dev`。安装脚本仅批准 esbuild。`scripts/prepare-assets.mjs` 校验指南 SHA-256 并复制原型规则、合成样稿及 PDF.js 字体/字库/WASM。`pnpm evaluate:structure` 在不监听端口的情况下运行两份合成 DOCX 的标注对照评测，写入 `验证记录/图表结构合成评测_0.4.json`。合成样稿的再生成脚本仅供开发者使用，不是浏览器运行依赖。

仓库附带规则、学院指南和合成样稿，可独立构建。若在开发工作区检测到相邻的 `审核核心试验版/`，资源准备脚本会从该目录同步规则和对应样稿。使用 `pnpm run build:pages` 生成 `docs/`，提交到 main 后由 GitHub Pages 发布。

浏览器保存运行配置及模型缓存；论文和报告仅在当前页面内存中，导出 JSON 是用户操作。没有教师历史、自动保存论文、跨设备同步或 DeepSeek 请求。本次会话最多保留5份、原文件合计160 MiB，明确选定的对照版本受保护，其余较早记录可能被释放；刷新即清空。

## 版本对比的使用

1. 先检查一份 DOCX/PDF，在“更多工具”中打开“版本对比”。
2. 点击“将当前版本设为对照”。请自行确认后续材料属于同一篇论文。
3. 在 Word/WPS 修改后点击“重新上传”。检查完成后，从“更多工具”回到“版本对比”，查看“仍检出 / 本次未检出 / 新增检出 / 无法判断”。
4. 可回看本次会话的任一份检查结果，或导出带文件哈希、规则与引擎依据的对照 JSON。

阶段、材料类型、引擎、规则或指南、规则开关、文档格式不一致时，不判断修正情况。比较按规则项目进行，不能自动证明前后是同一个错误位置；“本次未检出”可能来自修改、删去内容或覆盖范围变化，不等于教师确认修复。

可在“更多工具 → 示例稿”依次选择“Word 格式样稿”和“Word 修正对照稿”，按上述流程体验五项“本次未检出”的例子。`pnpm evaluate:versions` 可重现相同 DOCX 样稿的程序对照并生成验证记录，属于 Node 运行的集成验证，不是浏览器点击测试。

## 本轮验证

0.8.0 的合成 PDF 对照测试只改动三处正文字号，分别位于普通正文、同一行中的一个词、靠近页底的正文。带真实图像与题注的对照稿没有字号候选，改动稿检出这三处。缺少可辨认图像边界的孤立文字仍可能进入候选。开题栏目可以匹配正文中独立出现的常用标题，并在记录中保留实际标题和位置。

0.7.0 的 154 项自动测试及生产构建通过。合成 Word 测试分别检查偏小、偏大、正确以及无法确定的格式。模拟 DOM 中从首页打开示例稿，切换同段两条字号批注，保存教师评价，在另一版文稿登记漏报，导出结果保留两次提交各自的位置和反馈。模型协议、证据绑定和取消逻辑已通过回归测试。本轮未在浏览器 GPU 上复测实际生成，学院样稿上的误报率、漏报率和教师建议采纳率仍待验证。

0.6.0 的 131 项回归测试及生产构建通过。Word 示例稿经 React 与 docx-preview 在模拟 DOM 中显示，点击源段落 22 可查看同段四项格式问题，按 Enter 切换到关键词标记可查看相应建议及指南第 3 页。PDF 测试从实际示例文件读取带坐标的字号候选，对应指南第 6 页。本机启动器、脚本、样式和样稿通过 HTTP 检查。浏览器预览通道不可用，连线的实际像素位置和窄屏排版待真机目测。

2026-11-25：网页 112 项回归/集成测试、TypeScript 检查及生产构建通过。本轮浏览器操作通道不可用，0.5 布局与点击联动尚未实际浏览器复测，不能把 0.4 截图当作改版效果。原核心先前的 89 项测试通过，本轮未修改 Python 核心。M1 浏览器实际运行 Qwen3 1.7B 是先前 0.3/0.4 的验证；历史 Word/PDF 记录与截图见 `验证记录/`。仍未完成全断网及学院真实论文评测。

0.3.1 补充 Word 中文关键词数量、中文摘要长度试验估算及中英文摘要分类号线索。只有范围与分隔清楚时执行数量判断；摘要长度是建议提示，非硬性否决。图片、修订、表格、未闭合或重复摘要标题等情况保持人工确认。PDF 的这三项继续人工核对。

0.4.0 补充图表关联与覆盖清单。混合样稿 6 个主文档原生对象，其中 5 个图表、1 个公式；3 个题注可唯一关联、2 个同段图片待确认、1 处题注未关联。题注位置有 2 处偏差，编号有 3 处偏差。两份合成样稿的 5 条标注偏差均检出，未出现额外误报；这是小范围回归结果，不能代表真实论文准确率。教师确认的独立学院样稿仍待补充。

0.5.0 增加本次会话版本对比，并按用户选择改为文档审阅型布局。规则判定引擎仍为 `browser-audit-0.4.0`，本轮不改变学院审核规则。版本对照数据与测试记录见 `验证记录/版本对照合成评测_0.5.json`。
